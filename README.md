# devcontainer-features

Свои [Dev Container Features](https://containers.dev/implementors/features/) —
то, для чего нет готовых, а копировать из проекта в проект надоело. Здесь же
живут конфиги предсобранных образов (`images/`) и `devc` — CLI, который
разворачивает из них dev-контейнеры на build01. Как этим пользоваться —
в [USAGE.md](USAGE.md).

## Фичи

| Фича | Зачем |
|---|---|
| `gitleaks` | сканер секретов; нужен pre-commit хуку — без бинарника он предупреждает, но коммит не блокирует |
| `mise` | менеджер тулчейнов из apt-репозитория jdx, как на хосте; шимы в PATH login-шеллов. Тулчейны ставит `mise.toml` проекта |
| `claude-code` | Claude Code нативным установщиком: без Node, бинарник в `~/.local/bin` пользователя |
| `codex-cli` | полный статический OpenAI Codex bundle из GitHub Releases, включая Code Mode host; без Node и npm |
| `cargo-nextest` | готовый бинарник в `$CARGO_HOME/bin`; `cargo install` собирал бы его минуты |
| `android-sdk` | cmdline-tools, платформы и build-tools; выставляет `ANDROID_HOME` и `PATH` |
| `kotlin-lsp` | официальный Kotlin LSP от JetBrains |

## Использование

```jsonc
"features": {
  "ghcr.io/devcontainers/features/common-utils:2": { "username": "dev" },
  "ghcr.io/Takexito/devcontainer-features/mise:1": {},
  "ghcr.io/Takexito/devcontainer-features/claude-code:1": {},
  "ghcr.io/Takexito/devcontainer-features/codex-cli:2": {},
  "ghcr.io/Takexito/devcontainer-features/gitleaks:1": {},
  "ghcr.io/devcontainers/features/rust:1": {},
  "ghcr.io/Takexito/devcontainer-features/cargo-nextest:1": {}
}
```

`android-sdk` требует JDK, `cargo-nextest` — фичу `rust`; обе объявляют это
через `installsAfter`, но саму фичу java или rust нужно добавить самому.
`claude-code` и `codex-cli` ничего не требуют: Node им не нужен.

`kotlin-lsp` кладёт сервер в `/opt/kotlin-lsp/<версия>` и держит симлинк
`/opt/kotlin-lsp/current` — на него и стоит ссылаться в настройках редактора,
чтобы не переписывать пути при смене версии.

## Образы

`images/<стек>/devcontainer.json` — состав образов `base-dev`, `web-dev`,
`rust-dev` и `android-dev`; три последних строятся поверх `base-dev`.
Собирает и пушит их `devc build`, см. USAGE.md.

## Kotlin LSP протухает

Сборки живут **30 дней** — это осознанное решение JetBrains, сервер собран на
EAP-платформе IntelliJ. Симптом:

```
This build of intellij-server has expired.
```

Лечится подъёмом `version`. Ловушка: свежие сборки иногда появляются в
комментариях к issue раньше, чем в GitHub Releases, — если релизы выглядят
устаревшими, стоит заглянуть туда.

## Разработка

```sh
devcontainer features test --features gitleaks \
  --base-image mcr.microsoft.com/devcontainers/base:debian .

# фичам, которым нужны соседи, — через сценарий
devcontainer features test --skip-autogenerated --features android-sdk .

# devc
make build test lint
make install          # ~/.local/bin/devc и симлинк devproxy
```

Права на общие каталоги (`/opt/android-sdk`, `/opt/kotlin-lsp`) выдаются
**через группу**, а не сменой владельца. Причина: `devcontainer` по умолчанию
перемаппит uid пользователя под хостовой (`updateRemoteUserUID`) уже после
установки фич, и `chown`, сделанный на этапе сборки, перестаёт действовать.
Членство в группе перемаппинг переживает. Сгенерированные `devc` конфиги
ремап выключают (`updateRemoteUserUID: false`): uid `dev` совпадает с хостовым.
