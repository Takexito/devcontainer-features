# devcontainer-features

Свои [Dev Container Features](https://containers.dev/implementors/features/) —
то, для чего нет готовых, а копировать из проекта в проект надоело.

## Фичи

| Фича | Зачем |
|---|---|
| `gitleaks` | сканер секретов; нужен pre-commit хуку — без бинарника он предупреждает, но коммит не блокирует |
| `codex-cli` | OpenAI Codex CLI из npm; официальной фичи у OpenAI нет |
| `android-sdk` | cmdline-tools, платформы и build-tools; выставляет `ANDROID_HOME` и `PATH` |
| `kotlin-lsp` | официальный Kotlin LSP от JetBrains |

## Использование

```jsonc
"features": {
  "ghcr.io/devcontainers/features/java:1": { "version": "17" },
  "ghcr.io/Takexito/devcontainer-features/android-sdk:1": {
    "platforms": "34,35",
    "buildTools": "34.0.0"
  },
  "ghcr.io/Takexito/devcontainer-features/kotlin-lsp:1": {},
  "ghcr.io/Takexito/devcontainer-features/gitleaks:1": {},
  "ghcr.io/devcontainers/features/node:1": {},
  "ghcr.io/Takexito/devcontainer-features/codex-cli:1": {}
}
```

`android-sdk` требует JDK, `codex-cli` — npm; обе объявляют это через
`installsAfter`, но саму фичу java или node нужно добавить самому.

`kotlin-lsp` кладёт сервер в `/opt/kotlin-lsp/<версия>` и держит симлинк
`/opt/kotlin-lsp/current` — на него и стоит ссылаться в настройках редактора,
чтобы не переписывать пути при смене версии.

## Kotlin LSP протухает

Сборки живут **30 дней** — это осознанное решение JetBrains, сервер собран на
EAP-платформе IntelliJ. Симптом:

```
This build of intellij-server has expired.
```

Лечится подъёмом `version`. Ловушка: свежие сборки иногда появляются в
комментариях к issue раньше, чем в GitHub Releases, — если релизы выглядят
устаревшими, стоит заглянуть туда.

## Разработка

```sh
devcontainer features test --features gitleaks \
  --base-image mcr.microsoft.com/devcontainers/base:debian .

# фичам, которым нужны соседи, — через сценарий
devcontainer features test --skip-autogenerated --features android-sdk .
```

Права на общие каталоги (`/opt/android-sdk`, `/opt/kotlin-lsp`) выдаются
**через группу**, а не сменой владельца. Причина: `devcontainer` по умолчанию
перемаппит uid пользователя под хостовой (`updateRemoteUserUID`) уже после
установки фич, и `chown`, сделанный на этапе сборки, перестаёт действовать.
Членство в группе перемаппинг переживает.
